# ТЗ (предварительное): Калькулятор рассрочки — ЖК «Эко Сити Айни»

Версия 0.9 от 22.07.2026. Статус: черновик по итогам разбора боли. Открытые вопросы — в разделе 9, без их закрытия ТЗ не финальное.

## 1. Боль и цель

На переговорах менеджеры считают варианты графиков оплаты вручную на калькуляторе — медленно, ненаглядно, без следа. Согласованные графики не попадают в файл продаж: именно поэтому у всех рассрочек сейчас пустые параметры и колонка ПРОСРОЧКА врёт нулём.

Цель: экранный калькулятор для переговоров (смартборд / ноутбук / телефон), который наглядно показывает варианты рассрочки, а после сделки записывает согласованный график построчно в боевой файл продаж — закрывая дыру с параметрами рассрочек.

## 2. Принятые решения владельца (не пересматривать без него)

1. Вариант «100% оплата» в калькуляторе не показывается — такие сделки закрываются индивидуальной скидкой.
2. Матрица коэффициентов «цена от ПВ и срока» отклонена. Цена и скидка вводятся менеджером вручную, финальную цену по каждой сделке утверждает владелец лично (по телефону). Панель руководителя с минимальной ценой — убрана по его решению.
3. Схема расчёта: цена за м² × площадь → скидка (в % или $) → первый взнос суммой в $ → срок ползунком → ежемесячный платёж пересчитывается на лету.
4. Гибкие графики поддерживаются: «платежи по договорённости» (см. 5.3).

Зафиксированное предупреждение Клода (принято к сведению, отложено): при выходе на темп продаж 240 квартир личное утверждение каждой цены сделает владельца узким горлышком — вернуться к вопросу правил при росте потока.

## 3. Платформа и режимы

Web App на Google Apps Script, привязанный к боевому файлу продаж (бывшая тестовая копия, повышенная до боевой 21.07.2026; подлежит переименованию без «Тест»). Владелец скрипта — eralmaz@gmail.com. Доступ менеджерам — через «Поделиться», без хардкода почт в коде.

Два режима работы:

**«Прикидка»** — квартира не выбирается, площадь и цена вводятся руками. Для первого разговора. Кнопки «Зафиксировать» нет; на печатной форме пометка «предварительный расчёт».

**«По квартире»** — выбор реальной квартиры (подъезд → этаж → позиция/№), площадь и базовая цена подтягиваются из Реестра квартир автоматически. Если статус квартиры «бронь» или «продано» — видимое предупреждение (защита от одновременной торговли одной квартирой двумя менеджерами из четырёх). Только в этом режиме доступно «Зафиксировать».

## 4. Предпосылка: Реестр квартир (строится ДО калькулятора)

Текущий лист «Шахматка кв» — презентационный: все данные склеены текстом в одной ячейке, статус дублируется цветом заливки, покупатель и № ДДУ вписаны руками (ручная склейка уже плывёт: «Бактыяр · ДДУ-5» без фамилии). Машинным источником быть не может.

Решение:

1. Новый технический лист **«Реестр квартир»**: 240 строк, по колонке на факт — № квартиры (уникальный ключ), подъезд, этаж, позиция, комнат, площадь, базовая цена м², статус (Свободно / Бронь / Не в продаже / Продано), № ДДУ.
2. Статус «Продано» и № ДДУ не вводятся руками — тянутся из листа договоров по связи № ДДУ (устранение двойного ведения; урок школьного объекта: параллельные записи расходятся на миллионы незаметно).
3. Визуальная шахматка перестраивается на формулы от Реестра (текст и цвет ячеек генерируются). Ручные правки — только в Реестре.
4. Разовая миграция: скрипт парсит текущие ячейки шахматки в Реестр и выдаёт отчёт нераспознанных ячеек для ручной проверки глазами.

## 5. Функционал калькулятора (утверждён на демо v3)

### 5.1 Ввод сделки
Площадь (м²), цена за м² ($), скидка с переключателем % / $. Стоимость показывается с зачёркнутой ценой до скидки, ценой м² после скидки и суммой скидки — прозрачно для дольщика.

### 5.2 Взнос и срок
Первый взнос — суммой в $, рядом чипы 30/40/50/60/70% для быстрого заполнения; показывается, сколько это % от стоимости. Срок — ползунок 3–36 месяцев (диапазон уточнить, вопрос 9.3). Ежемесячный платёж — главная крупная цифра, пересчёт мгновенный.

### 5.3 Платежи по договорённости
Добавляемые строки «месяц № + сумма $» (например: 3-й месяц — $5 000, 7-й — $3 000). Остаток закрывается по переключателю:
- **Равными долями** — остаток делится на месяцы без договорённых платежей;
- **Хвостом в конце** — свободные месяцы по нулям, весь остаток одним финальным платежом.

Контрольная строка под главной цифрой: «Стоимость = взнос + договорённые + N × равный / + хвост» — всё сходится до доллара на глазах клиента.

### 5.4 Наглядность
Пропорциональная полоса платежей (взнос / договорённые / равные / хвост — разными цветами, с легендой). Раскрывающийся график платежей таблицей: №, дата, тип, сумма, остаток. Кнопка «Закрепить вариант» — снимок текущих настроек в карточку сравнения; рядом можно показать 2–3 закреплённых варианта (12 / 18 / 24 мес и т.п.). Печать / PDF для отправки дольщику в WhatsApp.

### 5.5 Защиты в интерфейсе
- Договорённые платежи превышают остаток → красная рамка и сумма превышения.
- Взнос больше стоимости → ограничение с пометкой.
- Хвост больше порога → предупреждение о риске неплатежа (порог — вопрос 9.2).
- Режим «По квартире»: статус Бронь/Продано → предупреждение.

## 6. «Зафиксировать» (сердце боевой версии)

Доступно только в режиме «По квартире». Записывает согласованный график **построчно** (каждый платёж: дата, тип, сумма) в параметры рассрочки договора в боевом файле продаж, со статусом «на согласовании» до утверждения владельцем. Это единственный канал появления графика в системе — устные договорённости без фиксации исключаются.

Юридическая связка: зафиксированный график должен выгружаться приложением к договору; формулировку приложения проверяет Гульмира до внедрения.

## 7. Тестирование и внедрение

По принципу владельца — тест только в демо, никаких тестовых данных в боевых файлах:

1. Нового тест-полигона после переезда 21.07.2026 нет → создать копию боевого файла продаж, она же полигон калькулятора.
2. До появления «Зафиксировать» калькулятор работает с Реестром строго read-only.
3. «Зафиксировать» обкатывается на полигоне на 2–3 сценариях (равные / договорённые / хвост), сверка построчной записи глазами — только потом переключение на боевой.
4. Формулы и структура проверяются по реальному файлу, не по памяти. Локаль русская (точки с запятой в формулах), часовой пояс Asia/Bishkek у всех участников.

## 8. Демо-артефакты (утверждённый макет)

Три итерации React-демо в чате «Калькулятор»: v1 (три карточки + матрица — отклонена), v2 (схема владельца + панель руководителя — панель убрана), **v3 — актуальный макет**: договорённые платежи, два режима остатка, пропорциональная полоса, сравнение вариантов. Дизайн боевого Web App повторяет v3 (палитра pine/sage/amber, крупная типографика под смартборд). Все цифры в демо вымышленные.

## 9. Открытые вопросы (закрыть до финального ТЗ)

1. **Где живёт базовая цена м²?** В ячейках шахматки её нет, подпись листа обрезана. Единая / по этажам / по типам / отдельный лист? Без этого Реестр не собрать.
2. **Порог хвоста** для предупреждения (например, хвост > 30% стоимости) — назначает владелец.
3. **Договорённые платежи:** по номерам месяцев (как в v3) или по реальным датам («в октябре после урожая») — определяет, нужен ли выбор дат.
4. **Структура листа договоров** в боевом файле: как связать № ДДУ ↔ квартира ↔ график платежей; куда именно пишет «Зафиксировать» (существующий лист рассрочек или новый).
5. **Печатная форма:** брендинг, реквизиты, язык (рус/кырг), пометки «предварительный расчёт» / «на согласовании».
6. **Доступы:** менеджеры сейчас на общем ecocityera@gmail.com, личные почты «скоро» — влияет на то, можно ли в «Зафиксировать» писать автора расчёта.
7. **Диапазон срока:** 3–36 мес или жёстко до даты сдачи дома.
